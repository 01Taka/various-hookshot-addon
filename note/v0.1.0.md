## Installation

Install in your addon's `package.json` pointing to the GitHub repository and release tag `v0.1.0`:

```json
{
  "dependencies": {
    "addon-utils": "github:01Taka/minecraft-addon-utils#v0.1.0"
  }
}
```

Or using pnpm:

```bash
pnpm add github:01Taka/minecraft-addon-utils#v0.1.0
```

All types, functions, classes, and constants are **directly imported from the package root (`"addon-utils"`)**:

```typescript
import {
  getMainhandItem,
  isHoldingItem,
  PlayerStateManager,
  PlayerDirectionResolver,
  calculateVelocityImpulse,
  calculateLiftImpulse,
  MINECRAFT_GRAVITY,
  MINECRAFT_DRAG,
} from "addon-utils";
```

> [!NOTE]
> **Subpath Encapsulation**:
> Subpaths (e.g. `addon-utils/item`) are encapsulated to prevent breaking changes when internal file layouts change. Always import directly from `"addon-utils"`.

## 1. Item / Equipment

Provides safe retrieval and inspection of player equipment states, item information, enchantments, and durability.

### Type Definitions

```typescript
export interface ItemDurability {
  /** Current consumed/damage value of the item (starts at 0 for unused items) */
  damage: number;
  /** Maximum durability of the item */
  maxDurability: number;
}
```

---

### Functions

#### `getEquippableComponent(player: Player): EntityEquippableComponent | undefined`
Retrieves the player's equippable component (`minecraft:equippable`).
- **Parameters**:
  - `player: Player`: Target player
- **Returns**: The equippable component, or `undefined` if unavailable or the player is invalid (e.g. disconnected)

#### `getEquipmentItem(player: Player, slot: EquipmentSlot): ItemStack | undefined`
Retrieves the item equipped in the specified equipment slot.
- **Parameters**:
  - `player: Player`: Target player
  - `slot: EquipmentSlot`: The target equipment slot (`EquipmentSlot.Mainhand`, `EquipmentSlot.Offhand`, `EquipmentSlot.Head`, etc.)
- **Returns**: The equipped `ItemStack`, or `undefined` if unequipped or empty

#### `getMainhandItem(player: Player): ItemStack | undefined`
Retrieves the item equipped in the player's mainhand.
- **Parameters**:
  - `player: Player`: Target player
- **Returns**: Mainhand `ItemStack`, or `undefined` if holding nothing

#### `getOffhandItem(player: Player): ItemStack | undefined`
Retrieves the item equipped in the player's offhand.
- **Parameters**:
  - `player: Player`: Target player
- **Returns**: Offhand `ItemStack`, or `undefined` if holding nothing

#### `isHoldingItem(player: Player, itemTypeId: string, slot?: EquipmentSlot): boolean`
Checks whether the player is holding an item with the specified type identifier.
- **Parameters**:
  - `player: Player`: Target player
  - `itemTypeId: string`: Target item type ID (e.g., `"minecraft:diamond_sword"`, `"custom:throwing_knife"`)
  - `slot?: EquipmentSlot`: Optional target slot. If omitted, returns `true` if held in either mainhand or offhand
- **Returns**: `true` if held in the specified slot (or either hand); otherwise `false`

#### `getEnchantmentLevel(item: ItemStack | undefined, enchantment: string | EnchantmentType): number`
Retrieves the level of the specified enchantment applied to an item.
- **Parameters**:
  - `item: ItemStack | undefined`: Target item (returns `0` if `undefined`)
  - `enchantment: string | EnchantmentType`: Enchantment ID or `EnchantmentType` (e.g., `"unbreaking"`, `"sharpness"`, `"efficiency"`)
- **Returns**: The enchantment level (positive integer >= 1). Returns `0` if not enchanted, invalid, or item is `undefined`

#### `getItemDurability(item: ItemStack | undefined): ItemDurability | null`
Retrieves durability metrics (current damage and max durability) for an item.
- **Parameters**:
  - `item: ItemStack | undefined`: Target item (returns `null` if `undefined`)
- **Returns**: `{ damage, maxDurability }`, or `null` if the item has no durability component or is invalid

---

### Usage Example

```typescript
import { Player, EquipmentSlot } from "@minecraft/server";
import {
  isHoldingItem,
  getMainhandItem,
  getEnchantmentLevel,
  getItemDurability,
} from "addon-utils";

function handlePlayerAttack(player: Player) {
  // 1. Check if holding a specific weapon in either hand
  if (!isHoldingItem(player, "minecraft:netherite_sword")) {
    return;
  }

  // 2. Inspect weapon, enchantment, and durability
  const weapon = getMainhandItem(player);
  const sharpnessLevel = getEnchantmentLevel(weapon, "sharpness");
  const durability = getItemDurability(weapon);

  if (durability) {
    const remaining = durability.maxDurability - durability.damage;
    player.sendMessage(`§7Remaining durability: ${remaining}/${durability.maxDurability} (Sharpness: Lv.${sharpnessLevel})`);
  }
}
```

## 2. Block / Direction

Provides block adjacency lookups, block face queries, and vector conversion for the Minecraft `Direction` enum.

### Functions

#### `getAdjacentBlock(block: Block, direction: Direction): Block | undefined`
Retrieves the block adjacent to the given block on the specified face.
- **Parameters**:
  - `block: Block`: Reference block
  - `direction: Direction`: Face direction to look up (`Direction.Up`, `Direction.Down`, `Direction.North`, `Direction.South`, `Direction.East`, `Direction.West`)
- **Returns**: Adjacent `Block` instance, or `undefined` if outside world bounds or in an unloaded chunk

#### `getDirectionVector(direction: Direction): Vector3`
Returns the unit vector (`Vector3` with length 1) corresponding to a Minecraft `Direction` enum.
- **Parameters**:
  - `direction: Direction`: Direction enum value
- **Returns**: Unit vector `{ x, y, z }` along that axis
  - `Up`: `{ x: 0, y: 1, z: 0 }`
  - `Down`: `{ x: 0, y: -1, z: 0 }`
  - `North`: `{ x: 0, y: 0, z: -1 }`
  - `South`: `{ x: 0, y: 0, z: 1 }`
  - `East`: `{ x: 1, y: 0, z: 0 }`
  - `West`: `{ x: -1, y: 0, z: 0 }`
  - Unknown/invalid direction: `{ x: 0, y: 0, z: 0 }`

#### `getOppositeDirection(direction: Direction): Direction`
Returns the opposite direction of the given `Direction`.
- **Parameters**:
  - `direction: Direction`: Reference direction
- **Returns**: The inverted `Direction` (e.g., `Up` -> `Down`, `North` -> `South`, `East` -> `West`)

---

### Usage Example

```typescript
import { Block, Direction } from "@minecraft/server";
import { getAdjacentBlock, getDirectionVector, getOppositeDirection } from "addon-utils";

function placeTorchOnWall(targetBlock: Block, hitFace: Direction) {
  // Get the opposite direction pointing back into the wall
  const wallDirection = getOppositeDirection(hitFace);

  // Check if the adjacent block in front of the hit face is air
  const placeTargetBlock = getAdjacentBlock(targetBlock, hitFace);
  if (placeTargetBlock && placeTargetBlock.isAir) {
    const normal = getDirectionVector(hitFace);
    // Proceed with raycast or block placement...
  }
}
```

## 3. State Management

### Class: `PlayerStateManager`
In-memory state manager keyed per-player.
Includes an automatic cleanup mechanism on player disconnection (`world.afterEvents.playerLeave`) to prevent memory leaks from stale addon state and caches.

#### Static Methods

#### `static set<T>(playerId: string, key: string, value: T): void`
Stores state data for the specified player.
- **Parameters**:
  - `playerId: string`: Player ID (`player.id`)
  - `key: string`: State key
  - `value: T`: Arbitrary value to store

#### `static get<T>(playerId: string, key: string, defaultValue: T): T`
Retrieves state data for the specified player. Returns `defaultValue` if not found.
- **Parameters**:
  - `playerId: string`: Player ID (`player.id`)
  - `key: string`: State key
  - `defaultValue: T`: Default fallback value if key or player is not registered
- **Returns**: Stored value or `defaultValue`

#### `static has(playerId: string, key: string): boolean`
Checks if a key exists for the specified player.
- **Parameters**:
  - `playerId: string`: Player ID (`player.id`)
  - `key: string`: State key to check
- **Returns**: `true` if key exists, otherwise `false`

#### `static delete(playerId: string, key: string): boolean`
Deletes a specific key for the specified player.
- **Parameters**:
  - `playerId: string`: Player ID (`player.id`)
  - `key: string`: State key to delete
- **Returns**: `true` if deleted successfully; `false` if key did not exist

#### `static clearPlayer(playerId: string): boolean`
Removes all state entries for the specified player from memory.
- **Parameters**:
  - `playerId: string`: Player ID (`player.id`)
- **Returns**: `true` if player entry existed and was removed; `false` otherwise

#### `static clearAll(): void`
Completely wipes all state entries across all players from memory.

#### `static registerAutoCleanup(): void`
Registers a listener to automatically clean up player state when they leave the server.
Call this once at addon startup (`main.ts`). Duplicate registrations are automatically prevented.

---

### Usage Example (Cooldown & Combo Management)

```typescript
import { Player, system } from "@minecraft/server";
import { PlayerStateManager } from "addon-utils";

const COOLDOWN_KEY = "skill_dash_last_tick";
const COOLDOWN_TICKS = 40; // 2 seconds

function tryExecuteDash(player: Player): boolean {
  const currentTick = system.currentTick;
  const lastTick = PlayerStateManager.get<number>(player.id, COOLDOWN_KEY, -9999);

  if (currentTick - lastTick < COOLDOWN_TICKS) {
    const remainSec = ((COOLDOWN_TICKS - (currentTick - lastTick)) / 20).toFixed(1);
    player.sendMessage(`§cCooldown: ${remainSec}s remaining`);
    return false;
  }

  // Update cooldown
  PlayerStateManager.set(player.id, COOLDOWN_KEY, currentTick);
  player.sendMessage("§aDash executed!");
  return true;
}
```

## 4. Player / Input

Provides admin permission checks, physical button press detection, posture-aware AABB calculations, and a **same-tick cached player direction resolver**.

### Type Definitions

```typescript
export interface IsPlayerAdminOptions {
  /** Array of tag names considered as admin (Default: ["admin", "op"]) */
  adminTags?: readonly string[];
  /** Whether to verify admin permissions via player tags (Default: true) */
  allowTagCheck?: boolean;
  /** Minimum command permission level considered admin (Default: levels higher than CommandPermissionLevel.Any) */
  minPermissionLevel?: CommandPermissionLevel;
}

export interface DirectionData {
  /** Original 3D vector */
  vector: Vector3;
  /** Unit vector normalized on the XZ (horizontal) plane (y=0, length=1; {0,0,0} if horizontal length is 0) */
  normalizedXZ: Vector3;
  /** Horizontal length / norm on the XZ plane (Math.hypot(x, z)) */
  horizontalLength: number;
}
```

---

### Functions

#### `isPlayerAdmin(player: Player, options?: IsPlayerAdminOptions): boolean`
Checks if the player has operator or administrator permissions (via OP command permission level or admin tags).
Operates safely across single-player and multiplayer environments; returns `false` for invalid/disconnected players.
- **Parameters**:
  - `player: Player`: Target player
  - `options?: IsPlayerAdminOptions`: Optional configuration to customize tags and permission levels
- **Returns**: `true` if player has admin rights; `false` otherwise

#### `isInputButtonPressed(player: Player, buttonName: string): boolean`
Inspects physical button press status across differing Bedrock versions and input devices safely.
- **Parameters**:
  - `player: Player`: Target player
  - `buttonName: string`: Name of the button (e.g., `"Sneak"`, `"Jump"`, `"Sprint"`)
- **Returns**: `true` if the physical button is pressed; `false` otherwise

#### `isSneakButtonPressed(player: Player): boolean`
Checks if the player is physically pressing the sneak (shift) key.
Avoids false positives from automatic game-engine sneaking (such as when entering 1-block spaces or crawling).
- **Parameters**:
  - `player: Player`: Target player
- **Returns**: `true` if the sneak button is physically pressed; `false` otherwise

#### `getMovementInputAngle(playerOrVector: Player | Vector2): number | null`
Returns the angle in radians of movement input relative to the player's forward direction.
Because Minecraft's `raw.x` treats left as positive (+) and right as negative (-), this function inverts `-vec.x` so that right is positive (+) and left is negative (-).
- **Parameters**:
  - `playerOrVector: Player | Vector2`: Player instance or movement Vector2 (`{ x, y }`)
- **Returns**: Angle in radians (`-π` to `+π`) with forward as 0, clockwise/right as positive (+), counter-clockwise/left as negative (-). Returns `null` if there is no movement input (standing still)

#### `getPlayerAABB(player: Player): AABB`
Calculates the current world-space bounding box (AABB) for the player.
Accounts for posture hitbox changes including standing, sneaking, swimming, and gliding.
- **Parameters**:
  - `player: Player`: Target player
- **Returns**: `AABB` with `min` and `max` coordinates

---

### Class: `PlayerDirectionResolver`
Resolves velocity, keyboard input, and view direction vectors, **caching results within the same game tick** to avoid redundant vector calculations across multiple callers.
Supports automatic memory cleanup on player disconnect (`world.afterEvents.playerLeave`).

#### Static Methods
#### `static get(player: Player): PlayerDirectionResolver`
Retrieves (or instantiates) the cached resolver instance for the player.
- **Parameters**:
  - `player: Player`: Target player
- **Returns**: `PlayerDirectionResolver` instance for the player

#### Properties (Getters)
- **`movement: DirectionData`**:
  Physical movement velocity information. Cached within the same tick.
- **`input: DirectionData`**:
  Input direction in the player's local space (standard 3D: x=right(+)/left(-), z=forward(+)/backward(-)). Cached within the same tick.
- **`worldInput: DirectionData`**:
  Intended movement direction in world space, synthesized from player horizontal yaw and keyboard input. Returns zero vector if no input. Cached within the same tick.
- **`view: DirectionData`**:
  Player view direction vector. Cached within the same tick.

---

### Usage Example (Directional Dash Skill)

```typescript
import { Player } from "@minecraft/server";
import { PlayerDirectionResolver, isSneakButtonPressed, isPlayerAdmin } from "addon-utils";

function handlePlayerSkill(player: Player) {
  // Check if sneak button is physically pressed
  if (!isSneakButtonPressed(player)) return;

  const resolver = PlayerDirectionResolver.get(player);

  // Retrieve player's world movement input direction
  const worldDir = resolver.worldInput;

  if (worldDir.horizontalLength > 0.1) {
    // Apply impulse toward intended movement input direction
    player.applyImpulse({
      x: worldDir.normalizedXZ.x * 1.2,
      y: 0.2,
      z: worldDir.normalizedXZ.z * 1.2,
    });
  } else {
    // Fallback: dash toward look direction if no directional input
    const viewDir = resolver.view;
    player.applyImpulse({
      x: viewDir.normalizedXZ.x * 0.8,
      y: 0.1,
      z: viewDir.normalizedXZ.z * 0.8,
    });
  }
}
```

## 5. Math / Geometry

Provides 3D and 2D (XZ-plane) geometric calculations and point-to-AABB distance calculations.

### Type Definitions

```typescript
export type VectorXZ = { x: number; z: number };

export interface AABB2D {
  min: VectorXZ;
  max: VectorXZ;
}

export interface AABB {
  min: Vector3;
  max: Vector3;
}

export interface AABBDistanceResult {
  /** Shortest distance to the AABB on the XZ (horizontal) plane (0 if inside on XZ) */
  horizontal: number;
  /** Shortest distance to the AABB on the Y (vertical) axis (0 if within height bounds) */
  vertical: number;
  /** Shortest straight-line Euclidean distance in 3D space to the AABB */
  distance: number;
  /** Per-axis outward excess distance (0 for axes within bounds) */
  delta: { dx: number; dy: number; dz: number };
  /** Signed vertical distance relative to AABB top face (point.y - maxY; positive=above, negative=below) */
  verticalTop: number;
  /** Signed vertical distance relative to AABB bottom face (point.y - minY; positive=above, negative=below) */
  verticalBottom: number;
}
```

---

### Functions

#### `calculatePointToAABBDistance(point: Vector3, aabb: AABB): AABBDistanceResult`
Calculates shortest distance metrics between a 3D point and an AABB.
- **Parameters**:
  - `point: Vector3`: Target point (e.g. player position)
  - `aabb: AABB`: Target AABB `{ min, max }`
- **Returns**: `AABBDistanceResult` containing horizontal, vertical, 3D euclidean distances, and signed top/bottom vertical distances

#### `getNearestFaceDirectionVector(vectorXZ: VectorXZ): Vector3`
Returns the unit cardinal face direction vector (`Vector3`: North, South, East, West) closest to the given horizontal vector.
- **Parameters**:
  - `vectorXZ: VectorXZ`: Horizontal vector (x, z)
- **Returns**: Cardinal unit vector (East: `{1,0,0}`, West: `{-1,0,0}`, South: `{0,0,1}`, North: `{0,0,-1}`). Returns `{0,0,0}` if zero vector. Defaults to X axis if |x| == |z|

---

### Usage Example

```typescript
import { Player, Block } from "@minecraft/server";
import { calculatePointToAABBDistance, AABB } from "addon-utils";

function checkPlayerLedgePosition(player: Player, block: Block) {
  const { x, y, z } = block.location;
  const blockAABB: AABB = {
    min: { x, y, z },
    max: { x: x + 1, y: y + 1, z: z + 1 },
  };

  const dist = calculatePointToAABBDistance(player.location, blockAABB);

  // Check if player is standing slightly above block top (0 to 0.3m) within 0.5m horizontal margin
  if (dist.verticalTop >= 0 && dist.verticalTop <= 0.3 && dist.horizontal < 0.5) {
    player.sendMessage("§aStanding near block ledge");
  }
}
```

## 6. Physics

Provides pure physics solvers that analytically reverse-engineer Minecraft Bedrock's environment physics (gravity, atmospheric/liquid drag) to achieve exact **target velocity tracking** and **exact apex height leaps**.
Functions are purely mathematical and do not rely on hardcoded defaults or external global state.

### Constants

```typescript
/** Standard free-fall gravity acceleration in Bedrock (blocks/tick) */
export const MINECRAFT_GRAVITY = 0.08;

/** Velocity retention ratio per tick (drag coefficient) by medium */
export const MINECRAFT_DRAG = {
  air: { y: 0.98, xz: 0.91 },
  water: { y: 0.8, xz: 0.8 },
  lava: { y: 0.5, xz: 0.5 },
  cobweb: { y: 0.05, xz: 0.25 },
  honey: { y: 0.2, xz: 0.2 },
  ground: { y: 0.98, xz: 0.546 },
  none: { y: 1.0, xz: 1.0 },
} as const;
```

---

### Type Definitions

```typescript
export interface CalculateVelocityImpulseParams {
  /**
   * Target velocity vector in blocks/tick.
   * If null or undefined is passed for an axis, external force control is skipped on that axis, preserving current momentum/acceleration.
   */
  targetVelocity: { x?: number | null; y?: number | null; z?: number | null };

  /** Current entity velocity (player.getVelocity()) */
  currentVelocity: Vector3;

  /** Y-axis velocity retention ratio (drag coefficient: 0.0 to 1.0) */
  dragY: number;

  /** XZ-axis velocity retention ratio (drag coefficient: 0.0 to 1.0) */
  dragXZ: number;

  /** Gravitational acceleration per tick (positive value to counteract gravity, 0 otherwise) */
  gravity: number;

  /** Delta time in ticks (Default: 1.0) */
  deltaTimeTick?: number;

  /** Stiffness of tracking. If null, targets immediate single-tick arrival (blend = 1.0). If positive, uses exponential decay smoothing */
  stiffness?: number | null;

  /** Maximum acceleration change clamp per tick (safety limiter) */
  maxAcceleration?: number;
}

export interface LiftPhysicsEnvironment {
  /** Free-fall gravity per tick (blocks/tick. Typically 0.08) */
  gravity: number;
  /** Y-axis velocity retention ratio (drag. Typically 0.98 in air) */
  dragY: number;
}

export interface LiftImpulseResult {
  /** Impulse vector to pass directly to entity.applyImpulse() (X and Z are 0) */
  impulse: Vector3;
  /** Number of discrete ticks required to reach apex (exact target height) */
  ticksToApex: number;
  /** Seconds required to reach apex (ticksToApex / 20) */
  timeToApexSeconds: number;
  /** Initial vertical velocity v0 in blocks/tick */
  initialVelocityY: number;
}
```

---

### Functions

#### `calculateVelocityImpulse(params: CalculateVelocityImpulseParams): Vector3`
Calculates the exact impulse vector needed to drive an entity toward a target velocity under environmental drag and gravity.
A pure mathematical function relying strictly on provided arguments.
- **Parameters**:
  - `params: CalculateVelocityImpulseParams`: Target velocity, current velocity, and environment parameters (`dragY`, `dragXZ`, `gravity`)
- **Returns**: Impulse vector (`Vector3`) to pass to `entity.applyImpulse()`

#### `calculateLiftImpulse(targetHeight: number, currentVelocity: Vector3, environment: LiftPhysicsEnvironment): LiftImpulseResult`
Calculates the exact vertical impulse required to reach a specific apex height difference (H blocks) above the launch position, taking discrete game-engine drag and gravity into account via numerical binary simulation.
- **Parameters**:
  - `targetHeight: number`: Target height elevation to reach (H > 0)
  - `currentVelocity: Vector3`: Current velocity (`player.getVelocity()`)
  - `environment: LiftPhysicsEnvironment`: Physics parameters (`gravity`, `dragY`)
- **Returns**: `LiftImpulseResult` containing the impulse vector and apex tick timing

---

### Usage Examples

#### 1. Target Speed Tracking (Hookshots & Dash Skills)
```typescript
import { Player } from "@minecraft/server";
import {
  calculateVelocityImpulse,
  MINECRAFT_GRAVITY,
  MINECRAFT_DRAG,
} from "addon-utils";

function pullPlayerTowardsTarget(player: Player, targetSpeedX: number, targetSpeedZ: number) {
  // Drive horizontal velocity toward target while counteracting gravity to hover
  const impulse = calculateVelocityImpulse({
    targetVelocity: {
      x: targetSpeedX,
      y: 0, // Y=0 maintains level flight
      z: targetSpeedZ,
    },
    currentVelocity: player.getVelocity(),
    gravity: MINECRAFT_GRAVITY, // 0.08
    dragY: MINECRAFT_DRAG.air.y, // 0.98
    dragXZ: MINECRAFT_DRAG.air.xz, // 0.91
    stiffness: 8.0, // Smooth exponential tracking
    maxAcceleration: 0.5, // Acceleration clamp limiter
  });

  player.applyImpulse(impulse);
}
```

#### 2. Auto-jump / Ledge Leap (Exact Apex Elevation)
```typescript
import { Player, system } from "@minecraft/server";
import {
  calculateLiftImpulse,
  MINECRAFT_GRAVITY,
  MINECRAFT_DRAG,
} from "addon-utils";

function performStepJump(player: Player, stepHeightBlocks: number = 1.2) {
  // Calculate vertical impulse needed to reach exactly 1.2 blocks higher
  const { impulse, ticksToApex } = calculateLiftImpulse(
    stepHeightBlocks,
    player.getVelocity(),
    { gravity: MINECRAFT_GRAVITY, dragY: MINECRAFT_DRAG.air.y }
  );

  player.applyImpulse(impulse);

  // Trigger effect precisely at apex
  system.runTimeout(() => {
    if (player.isValid) {
      player.dimension.spawnParticle("minecraft:wind_explosion_emitter", player.location);
    }
  }, ticksToApex);
}
```

## Implementation Guidelines & Best Practices for AI

1. **Memory Cleanup Principle**:
   - Always call `PlayerStateManager.registerAutoCleanup()` once during addon startup in `main.ts` when using `PlayerStateManager`.
2. **Direction Resolution Principle**:
   - When inspecting player look or movement input vectors, always use [`PlayerDirectionResolver.get(player)`](#class-playerdirectionresolver) rather than manual trigonometry or `player.inputInfo`. Its same-tick caching prevents duplicate math across multiple addon systems.
3. **Explicit Physics Injection**:
   - When calling `calculateVelocityImpulse` or `calculateLiftImpulse`, do not hardcode magic numbers; pass values from `MINECRAFT_GRAVITY` and `MINECRAFT_DRAG` constants. For non-standard media (underwater, low-gravity), pass the appropriate constants explicitly.
4. **Preserving Natural Momentum on Specific Axes**:
   - Pass `null` or `undefined` for axes in `targetVelocity` where you want natural physics (e.g., standard free-fall) to proceed untouched without impulse overrides.
